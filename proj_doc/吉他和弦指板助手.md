# 吉他和弦指板助手（暂定名）——项目需求文档

> 文档版本：v1.1  
> 项目目标：作为 Flutter 初学者的练习项目，逐步开发一款可在 Android 和 Windows 上运行的吉他和弦查询工具。  
> 当前阶段：需求与学习路线规划，采用“先简化交互、再升级完整指板”的开发策略；第一版覆盖常见和弦及一组扩展和弦。

---

## 1. 项目背景与目标

开发一款帮助吉他学习者理解音符、音程、和弦构成及常用指法的应用。用户可以在虚拟吉他指板上选择音符，应用分析可能的和弦；也可以输入和弦名称，查看该和弦包含的音，以及常见的吉他按法。

本项目同时作为 Flutter 入门实战，优先采用容易理解、容易调试的实现方式，避免一开始引入复杂架构、数据库、网络服务或过多第三方库。

### 1.1 核心目标

1. 展示可交互的吉他指板。
2. 用户点选指板上的音符后，显示所选音符及其音名。
3. 根据用户选择的音符集合，推测可能对应的和弦。
4. 用户输入和弦名称后，显示和弦构成音，并在指板上标出这些音。
5. 提供常见和弦指法图，展示弦、品、按弦手指等信息。
6. 支持 Android 与 Windows，尽可能复用同一套 Flutter 代码。
7. 将功能拆分为适合初学者逐步完成的小任务。

### 1.2 暂不追求的目标

第一版不要求：
- 在线账号、云同步或社交功能。
- 音频识别、麦克风听和弦。
- 自动识别真实吉他照片。
- 完整覆盖所有复杂和弦、转位、调式与特殊调弦。
- 一开始就制作复杂动画或精美视觉效果。
- 一开始就接入数据库或后端服务。

## 2. 目标用户与典型使用场景

### 2.1 目标用户

- 正在学习吉他、想查询和弦构成音的用户。
- 想通过指板理解音符分布的初学者。
- 希望查找常用和弦按法的用户。

### 2.2 使用场景

**场景 A：从和弦查指板**
1. 用户输入 `C`。
2. 应用识别 C 大三和弦。
3. 应用展示构成音 C、E、G。
4. 指板上所有可见的 C、E、G 位置高亮显示。
5. 用户可以查看常见 C 和弦按法。

**场景 B：从指板选音猜和弦**
1. 用户在指板上依次选择几个音。
2. 应用汇总当前选择的音名。
3. 用户点击“分析和弦”。
4. 应用列出匹配或接近的和弦，并说明构成音。
5. 如果存在多个可能结果，应展示多个候选，而不是强行只给一个答案。

**场景 C：查看指法**
1. 用户打开某个和弦，例如 `G`。
2. 应用展示一种或多种常用指法。
3. 指法图标出每根弦的状态、按弦品位、手指编号，以及开放弦或不弹奏的弦。
4. 用户可以切换不同按法。

## 3. 名词与基础规则

### 3.1 音名

第一版使用十二平均律中的十二个音级：

`C、C#、D、D#、E、F、F#、G、G#、A、A#、B`

后续可以增加等音显示，例如 `C# / Db`。第一版建议内部统一使用一种标准音名，避免同一个音被重复计算。

### 3.2 和弦构成音

和弦不是简单的“任意三个音”，而是由根音和特定音程关系构成。例如：

- C 大三和弦：C、E、G。
- A 小三和弦：A、C、E。
- G7：G、B、D、F。

需要注意：和弦通常依据音程关系判断，而不是只看音名数量；同一个音可以在指板上出现多个位置，和弦也可能有重复音、不同排列或转位。

### 3.3 吉他指板

第一版默认：
- 标准调弦：从第 6 弦到第 1 弦为 E、A、D、G、B、E。
- 六根弦。
- 默认显示 0 至 12 品；屏幕空间不足时允许横向滚动。
- 0 品表示空弦。
- 每向高一品，音高升高半音。
- 指板显示采用“横向表示品位、纵向表示琴弦”的布局。界面上必须清楚标明第 6 弦和第 1 弦，避免方向混淆。

后续可考虑自定义调弦、扩展到 24 品、左手吉他模式等。

## 4. 功能需求

### 4.1 首页

首页提供两个主要入口：
- **按和弦查指板**
- **选音分析和弦**

可以在首页显示最近查看的和弦，但该功能不属于第一阶段必做项。

### 4.2 吉他指板组件

指板是本应用最重要的 UI 组件。

#### 必须具备
- 显示六根弦与品格线。
- 显示品位编号。
- 显示每个位置对应的音名，或在需要时显示音名。
- 可以点击位置来选择或取消选择音符。
- 能高亮当前和弦包含的所有音。
- 能区分“用户主动选择的音”和“和弦查询产生的高亮音”。
- 提供“清空选择”功能。
- Android 竖屏可用；Windows 窗口缩放时布局不应溢出。

#### 建议交互
- 用户点选某个品位后，该位置出现圆点或高亮。
- 再次点击同一位置可以取消选择。
- 同一个音名在指板不同位置出现时，允许全部高亮。
- 提供显示模式切换：显示音名 / 只显示高亮音名。
- 选中音符列表显示去重后的音名；如有需要，可同时显示具体弦和品位。

#### 验收标准
- 六根弦与品位位置关系正确。
- 标准调弦下各品位音名计算正确。
- 点击与取消选择行为符合预期。
- 窗口变宽或变窄时，指板仍可正常查看和操作。

### 4.3 按和弦名称查询

#### 输入方式
第一版优先提供：
- 搜索框输入和弦名，例如 `C`、`Am`、`G7`、`Dm`。
- 常用和弦快捷列表。

第一版支持的和弦类型：
- 大三和弦：C、D、E、F、G、A、B。
- 小三和弦：Cm、Dm、Em、Fm、Gm、Am、Bm。
- 属七和弦：C7、D7、E7、G7、A7 等。
- 大七和弦：Cmaj7、Fmaj7 等。
- 小七和弦：Am7、Dm7、Em7 等。
- 挂二和弦：Csus2、Dsus2 等。
- 挂四和弦：Csus4、Dsus4 等。
- 减三和弦：Cdim 等。
- 增三和弦：Caug 等。

和弦类型应通过统一的数据定义描述，不要为每种和弦单独编写一套计算逻辑。暂时不认识的输入要显示友好提示，而不是崩溃。

#### 查询结果
- 展示和弦标准名称。
- 展示根音。
- 展示构成音。
- 在指板上高亮所有属于该和弦的音级位置。
- 显示当前和弦可用的常见指法。
- 切换指法时，指法图与对应品位信息同步变化。

#### 验收标准
- 输入 `C` 后显示 C、E、G，并高亮指板上所有 C、E、G 音级位置。
- 输入 `Am` 后显示 A、C、E。
- 输入无效和弦时显示提示。
- 同一个音名在不同弦、不同品位上的位置都能正确高亮。

### 4.4 从选中音符分析和弦

#### 操作流程
1. 用户在指板上选择音符。
2. 页面显示所选音名。
3. 用户点击“分析和弦”。
4. 应用返回可能的和弦列表。
5. 用户选择一个候选后，可查看其构成音和常用指法。

#### 第一版规则
- 将选中位置转换为音级集合，分析时先忽略八度差异。
- 重复选择相同音级时，在和弦匹配中只计一次，但界面可以保留具体位置。
- 使用内置和弦定义进行匹配。
- 若存在多个匹配结果，全部列出，并按简单规则排序。
- 如果没有匹配结果，提示用户尝试增减音符，不应随意猜测一个和弦。

#### 重要说明
只凭音符集合不一定能唯一确定和弦。例如，同一组音在不同根音解释下可能对应不同和弦；不包含根音的选音也可能是某个和弦的部分音。因此结果应称为“可能的和弦”，而不是绝对答案。

#### 验收标准
- 选择 C、E、G 后，候选列表中能出现 C 大三和弦。
- 选择 A、C、E 后，候选列表中能出现 Am。
- 选音不足或不匹配时能显示清楚的提示。
- 候选结果不唯一时可以展示多个候选。

### 4.5 常用和弦指法图

#### 指法图需要显示
- 六根弦。
- 品格线与必要的品位范围。
- 每根弦的状态：按弦、开放弦、不弹奏。
- 按弦位置与手指编号（1、2、3、4）。
- 和弦名称。
- 可选的指法备注。

#### 数据范围
第一版建议手动整理常见开放和弦：
- C、A、G、E、D。
- Am、Dm、Em。
- 后续再增加 F、Bm、横按和弦及其他变体。

注意：第一版支持某种和弦的“理论构成音查询”，不代表必须同时提供该和弦的真实吉他指法。扩展和弦的指法数据可逐步补充；没有录入指法时，应明确显示“暂未收录常用指法”，不能生成未经验证的按法。

每个和弦可以有多种指法，应用应允许切换。

#### 验收标准
- 指法图与所存储的弦、品、手指数据一致。
- 开放弦与不弹奏弦能够明显区分。
- 切换指法时，图形和文字信息正确更新。

### 4.6 基础设置（后续功能）

- 调弦选择。
- 指板品数选择。
- 音名显示方式选择。
- 左手 / 右手指板方向。
- 深色模式。

这些功能不属于最初的 MVP，等核心流程完成后再做。

## 5. 页面规划

### 页面一：首页
- 应用名称。
- “按和弦查指板”入口。
- “选音分析和弦”入口。
- 常用和弦快捷入口（可后续实现）。

### 页面二：指板与和弦查询页
- 顶部：和弦搜索框与清空按钮。
- 中部：和弦名称、构成音列表。
- 主区域：吉他指板。
- 下方：常见指法列表与指法图。
- 选音模式下：显示已选音列表、“清空”和“分析和弦”按钮。

初学者可以先把两个模式放在同一个页面中，通过状态切换实现，避免一开始写太多页面。

## 6. 数据与核心逻辑设计

建议先把音乐计算逻辑与 UI 分开，但不要一开始就引入复杂的架构。

### 6.1 音符数据

每个指板位置可由以下信息计算：
- 弦编号。
- 品位。
- 空弦音级。
- 当前音级。
- 显示音名。

计算思路：当前音级 =（空弦音级 + 品位）对 12 取余。

内部可将十二个音级编号为 0 至 11，例如 C=0、C#=1、D=2……B=11。

### 6.2 和弦定义

每种和弦类型使用“根音 + 音程偏移”表示。例如：
- 大三和弦：`[0, 4, 7]`
- 小三和弦：`[0, 3, 7]`
- 属七和弦：`[0, 4, 7, 10]`

查询时根据根音和音程偏移计算构成音，再映射成音名。

### 6.3 和弦识别

- 把用户选中的音名转换成 0 至 11 的音级编号。
- 去重并排序。
- 与内置和弦定义的音级集合比较。
- 返回所有匹配结果。
- 后续再考虑不完整和弦、转位、根音推断和结果排序优化。

### 6.4 指法数据

指法数据建议与和弦构成音数据分开保存。

一条指法至少需要记录：
- 和弦标识。
- 指法名称或说明。
- 六根弦各自的品位；可以约定 `-1` 表示不弹，`0` 表示开放弦，正整数表示按下的品位。
- 对应手指编号；开放弦与不弹奏弦不需要手指编号。
- 可选的横按信息。

第一版可以直接使用 Dart 常量保存，不需要数据库。等用户可以自行添加、编辑和保存指法后，再考虑本地数据库。

## 7. 技术方案建议

### 7.1 技术栈
- Flutter + Dart。
- Android 与 Windows 共用 UI 和业务逻辑。
- 初期只使用 Flutter 自带组件。
- 指板可先用 `CustomPaint` 绘制，也可以先使用 `Row`、`Column`、`GestureDetector` 等基础组件制作简化版。建议先做简化版，再考虑 `CustomPaint`。
- 第一版使用内存中的 Dart 集合与常量数据，不接后端。

### 7.2 代码组织建议

初学阶段建议按职责简单拆分：
- `models/`：音符、和弦、指法等数据模型。
- `data/`：内置和弦和指法数据。
- `logic/`：音级计算、和弦构成音计算、和弦匹配。
- `widgets/`：吉他指板、指法图等可复用 UI。
- `pages/`：页面。
- `main.dart`：应用入口。

如果一开始不熟悉目录拆分，可以先写在少量文件中；每完成一个功能，再把相对独立的部分移动到合适文件。不要为了“架构正确”而提前创建大量抽象类。

### 7.3 状态管理
第一版可以先使用 `StatefulWidget` 和 `setState` 管理页面状态。等页面状态变复杂、能清楚解释为什么需要状态管理后，再考虑 Provider 或 Riverpod。不要为了学习这个项目而同时学习过多新工具。

### 7.4 平台支持
- 开发阶段优先在一个平台完成主要功能，例如 Windows 或 Android。
- 核心逻辑不依赖平台 API，后续再检查另一个平台的布局和交互。
- 在 Android 与 Windows 上分别测试窗口尺寸、点击反馈、字体和滚动行为。

## 8. 非功能需求

- **易用性：** 核心操作尽量直观，按钮名称清楚。
- **正确性：** 音级计算、和弦构成音和指法数据应可测试。
- **可维护性：** 音乐计算逻辑不要全部写在 UI 的 `build()` 方法中。
- **响应速度：** 指板高亮与选音反馈应即时完成。
- **跨平台：** 核心功能在 Android 与 Windows 上行为一致。
- **容错性：** 无效输入、无匹配和弦、未选择音符等情况都应有提示。
- **离线使用：** 第一版不依赖网络，打开应用即可查询。

## 9. MVP 范围与优先级

### P0：第一版必须完成
- [ ] 先用音符列表或简化指板验证音名计算与选音交互，不要求一开始完成完整指板。
- [ ] 正确计算标准调弦下任意弦、品对应的音名。
- [ ] 可以选择、取消选择音符，并显示已选音符。
- [ ] 输入和弦名称并显示构成音，至少支持大三、小三、属七、maj7、m7、sus2、sus4、dim、aug。
- [ ] 选中音符后能匹配内置和弦，允许返回多个候选。
- [ ] 在简化指板上高亮当前和弦的构成音；核心逻辑稳定后再升级完整 0 至 12 品指板。
- [ ] 显示至少 C、G、D、A、E、Am、Dm、Em 的常用指法。
- [ ] 扩展和弦即使暂时没有指法数据，也能正常显示构成音并提示未收录指法。
- [ ] Android 与 Windows 均可启动和使用核心功能。

### P1：核心功能完成后
- [ ] 更多和弦类型与更多指法。
- [ ] 多个候选和弦的排序与说明。
- [ ] 指板显示模式切换。
- [ ] 最近查询记录。
- [ ] 深色模式。

### P2：未来扩展
- [ ] 自定义调弦、左手模式、扩展品位。
- [ ] 收藏和用户自定义指法。
- [ ] 本地保存用户数据。
- [ ] 音频播放或和弦听辨辅助。
- [ ] 和弦转位、扩展和弦、不完整和弦识别。

## 10. 测试与验收

### 10.1 音符计算测试
- 标准调弦第 6 弦空弦为 E。
- 第 6 弦第 1 品为 F。
- 第 5 弦空弦为 A。
- 第 1 弦空弦为 E。
- 同一根弦每升高 12 品，音名循环一次。

### 10.2 和弦构成音测试
- C → C、E、G。
- Am → A、C、E。
- G7 → G、B、D、F。
- Cm → C、D#、G（显示时可按约定显示为 Eb）。

### 10.3 交互测试
- 选中一个位置后，选中状态可见。
- 再次点击同一位置后，选中状态取消。
- 清空按钮能清除所有手动选音。
- 查询和弦后，构成音高亮正确。
- 无效输入有提示，不导致应用异常。

### 10.4 跨平台测试
- Android 上能正常点击指板、输入和弦、查看指法。
- Windows 上能正常点击指板、输入和弦、查看指法。
- 窗口缩放时没有严重溢出或无法点击的问题。

## 11. 开发约定

1. 每一步先完成最小可运行版本，再继续下一步。
2. 每完成一个阶段，都要在 Android 或 Windows 至少一个平台运行验证。
3. 尽量先自己实现；遇到问题时先描述现象、查看报错，再寻求帮助。
4. 先理解代码为什么这样写，再复制代码；每次新增代码都要能说清楚主要变量、函数和状态的用途。
5. 先保证功能正确，再改善视觉效果。
6. 每一步完成后进行一次 Git 提交，记录当前进度。
7. 不要同时引入多个新概念：一个阶段主要学习一到两个新知识点。

## 12. 初学者学习路线（从零到完成项目）

> 建议按顺序推进。每一步都包含学习重点、开发任务与完成标准。可以按实际掌握速度调整，不要求每天完成固定数量的步骤。

### 第 1 步：创建 Flutter 项目并运行

**学习内容**
- Flutter 项目目录。
- `main()`、`runApp()`。
- `MaterialApp`、`Scaffold`。
- Android / Windows 运行方式。

**开发任务**
- 创建项目，例如 `guitar_chord_helper`。
- 先在一个平台运行默认示例，再清理示例代码。
- 页面显示应用标题“吉他和弦助手”和一段欢迎文字。

**完成标准**
- 能独立启动项目。
- 能找到入口文件并解释应用从哪里开始运行。

## 13. 建议的每次学习节奏

每次学习可以按以下顺序进行：

1. **先理解目标（5–10 分钟）：** 今天要解决哪个具体问题？
2. **自己尝试（20–40 分钟）：** 先写出最简单的版本。
3. **查资料或求助（按需）：** 遇到错误时先读报错、定位问题，不要直接重写全部代码。
4. **运行验证（10–20 分钟）：** 用几个已知结果检查功能是否正确。
5. **复盘（5 分钟）：** 写下今天学会了什么、还不理解什么、下一步做什么。

建议给每一步设置一个可见成果，例如一个页面、一段可验证的计算函数或一个能点击的指板。初学阶段，**先完成、再理解、再重构**，比一开始追求完整架构更有效。

## 14. 后续可补充的问题

本需求文档先按“标准调弦、六弦吉他、离线使用、初学者项目、先简化交互再升级完整指板、第一版支持常见及指定扩展和弦”制定。后续可以根据实际需要确认：

1. 完整指板未来需要显示到 12 品，还是进一步扩展到 24 品？
2. 音名是否只显示 C、D、E 等字母，还是也要显示 Do、Re、Mi？
3. 反向识别后续是否需要支持不完整和弦、转位和根音推断？
4. 常见指法是否只需要标准开放和弦，还是也要支持横按和弦与同一和弦的多种把位？

以上问题不影响开始开发，建议先按本文 MVP 推进，遇到实际需求再扩展。
