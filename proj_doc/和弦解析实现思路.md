# 吉他和弦指板助手 --- 和弦解析实现思路

> 本文专门说明"从用户选择的指板位置，推断可能的和弦"这一核心功能应该如何实现。
>
> 配套文档：`future.md`
> 负责整体开发阶段规划；本文负责和弦解析模块的具体实现拆解、数据流、算法步骤和测试方法。

------------------------------------------------------------------------

## 一、先明确：和弦解析到底要解决什么问题？

用户在吉他指板上选择若干弦和品位，例如：

-   5 弦 3 品
-   4 弦 2 品
-   3 弦空弦
-   2 弦 1 品
-   1 弦空弦

程序不能直接根据"5 弦 3 品"判断它是 C 和弦，而应该分成几个步骤：

1.  根据吉他的调弦方式，把弦号和品位转换成实际音符。
2.  将实际音符转换成便于计算的半音值。
3.  去掉重复的音高类别，得到这组音符包含哪些音。
4.  尝试不同的根音，计算每个音相对于根音的音程。
5.  将音程集合与和弦公式库比较。
6.  返回可能的和弦候选，并根据匹配情况排序。

因此，整体数据流是：

``` text
FretboardNote
    │
    ▼
NoteCalculator
    │ 计算每根弦实际发出的音符
    ▼
List<GuitarNote>
    │
    ▼
PitchClassExtractor
    │ 去重，得到音高类别集合
    ▼
Set<int>
    │
    ▼
ChordAnalyzer
    │ 枚举根音、计算音程、匹配公式
    ▼
List<ChordMatchResult>
    │
    ▼
UI 展示和弦候选
```

第一版先实现精确匹配。转位、缺音、模糊匹配和音乐上下文排序都放到后续阶段。

## 二、几个必须理解的乐理概念

### 2.1 十二音与半音值

在常见十二平均律中，一个八度分成 12
个半音。为了方便程序计算，可以给十二个音分配 0～11 的数字：

  音名        半音值
  --------- --------
  C                0
  C# / Db          1
  D                2
  D# / Eb          3
  E                4
  F                5
  F# / Gb          6
  G                7
  G# / Ab          8
  A                9
  A# / Bb         10
  B               11

这里的数字表示音高类别（Pitch Class），不表示具体八度。

例如，低音 E 和高音 E 的 Pitch Class 都是 4，但它们实际音高不同。

### 2.2 指板位置如何产生音符

标准吉他调弦从 6 弦到 1 弦：

  弦号   空弦音     Pitch Class
  ------ -------- -------------
  6      E                    4
  5      A                    9
  4      D                    2
  3      G                    7
  2      B                   11
  1      E                    4

每升高一品，音高升高一个半音。

因此：

``` text
实际音高 = 空弦音高 + 品位
Pitch Class = 实际音高 % 12
```

例如 5 弦 3 品：

``` text
A = 9
9 + 3 = 12
12 % 12 = 0
结果是 C
```

注意：如果要判断最低音和转位，不能只保存 `% 12`
后的值，还需要保留完整音高，例如 MIDI 音高编号或等价的绝对半音编号。

### 2.3 和弦公式是什么

和弦公式描述的是"各个音相对于根音相差多少个半音"。

例如：

  和弦    半音公式      以 C 为根音时
  ------- ------------- ---------------
  major   0、4、7       C、E、G
  minor   0、3、7       C、Eb、G
  dim     0、3、6       C、Eb、Gb
  aug     0、4、8       C、E、G#
  sus2    0、2、7       C、D、G
  sus4    0、5、7       C、F、G
  maj7    0、4、7、11   C、E、G、B
  7       0、4、7、10   C、E、G、Bb
  m7      0、3、7、10   C、Eb、G、Bb

例如 C major 的公式是 `[0, 4, 7]`。D major 也是
`[0, 4, 7]`，只不过根音从 C 变成了 D。

这就是为什么不需要为每个根音都单独编写识别规则。

## 三、模块一：把指板位置转换成音符

### 3.1 输入和输出

输入：一组 `FretboardNote`。

``` dart
class FretboardNote {
  final int string;
  final int fret;
  final int? finger;
}
```

输出：实际音符模型。

``` dart
class GuitarNote {
  final String name;
  final int pitchClass; // 0~11，不包含八度
  final int midiNumber; // 保留绝对音高，便于比较高低

  const GuitarNote({
    required this.name,
    required this.pitchClass,
    required this.midiNumber,
  });
}
```

`finger` 是演奏指法信息，不影响音符的音高计算，所以第一版
`NoteCalculator` 不需要使用它。

### 3.2 调弦配置

不要把标准调弦直接散落在计算函数里。可以把每根弦的空弦音高放到一个配置中：

``` dart
class GuitarTuning {
  final Map<int, int> openStringMidi;

  const GuitarTuning({
    required this.openStringMidi,
  });

  static const standard = GuitarTuning(
    openStringMidi: {
      6: 40, // E2
      5: 45, // A2
      4: 50, // D3
      3: 55, // G3
      2: 59, // B3
      1: 64, // E4
    },
  );
}
```

这里使用 MIDI 编号只是为了保留音高和八度。只要项目统一使用同一套 MIDI
编号约定即可。

### 3.3 计算步骤

建议实现一个 `NoteCalculator`：

``` dart
class NoteCalculator {
  final GuitarTuning tuning;

  const NoteCalculator({
    required this.tuning,
  });

  GuitarNote calculate(FretboardNote position) {
    final openMidi = tuning.openStringMidi[position.string];

    if (openMidi == null) {
      throw ArgumentError('无效的弦号：${position.string}');
    }

    if (position.fret < 0) {
      throw ArgumentError('品位不能小于 0');
    }

    final midi = openMidi + position.fret;
    final pitchClass = midi % 12;

    const noteNames = [
      'C', 'C#', 'D', 'D#', 'E', 'F',
      'F#', 'G', 'G#', 'A', 'A#', 'B',
    ];

    return GuitarNote(
      name: noteNames[pitchClass],
      pitchClass: pitchClass,
      midiNumber: midi,
    );
  }
}
```

这是实现示例。后续若需要支持降号显示、不同调性下的拼写（例如 Bb 而不是
A#），应另外设计音名显示策略，不要影响底层音高计算。

### 3.4 必须通过的测试

标准调弦：

  输入        预期音名     MIDI 示例
  ----------- ---------- -----------
  6 弦空弦    E                   40
  5 弦空弦    A                   45
  5 弦 3 品   C                   48
  4 弦 2 品   E                   52
  3 弦空弦    G                   55
  2 弦 1 品   C                   60
  1 弦空弦    E                   64

测试重点：

-   同一个音名在不同弦上出现时，Pitch Class 应相同。
-   不同八度的 MIDI 编号应不同。
-   空弦必须按 0 品处理。
-   非法弦号和非法品位需要明确处理。

**本模块完成后，其他模块不应该再自己计算"某弦某品是什么音"。统一调用
`NoteCalculator`。**

## 四、模块二：提取音高类别并去重

### 4.1 为什么要去重？

例如一个 C major 指法实际弹出：

``` text
C、E、G、C、E
```

和弦识别第一版只关心有哪些不同的音高类别，因此可以转换成：

``` text
{C、E、G}
```

重复弹奏 C 或 E 不会改变这组音的基础和弦公式。

### 4.2 实现思路

``` dart
Set<int> extractPitchClasses(List<GuitarNote> notes) {
  return notes.map((note) => note.pitchClass).toSet();
}
```

得到的集合只用于基础公式匹配。

同时不要丢掉原始
`List<GuitarNote>`，因为后续判断最低音、音域和转位时还需要完整音高。

建议在分析流程中同时保留：

``` dart
final List<GuitarNote> playedNotes; // 原始弹奏音符，保留八度
final Set<int> pitchClasses;        // 去重后的音高类别
```

### 4.3 测试

``` text
输入：C、E、G、C、E
输出：{C、E、G}
```

还需要测试：

-   输入顺序改变，集合内容不变。
-   相同音高重复多次，集合中只保留一个值。
-   不同八度的同名音，Pitch Class 相同，但原始音符仍然保留。

## 五、模块三：建立和弦公式库

### 5.1 定义公式模型

``` dart
class ChordFormula {
  final String suffix;
  final List<int> intervals;

  const ChordFormula({
    required this.suffix,
    required this.intervals,
  });
}
```

例如：

``` dart
const chordFormulas = [
  ChordFormula(suffix: 'major', intervals: [0, 4, 7]),
  ChordFormula(suffix: 'minor', intervals: [0, 3, 7]),
  ChordFormula(suffix: 'dim', intervals: [0, 3, 6]),
  ChordFormula(suffix: 'aug', intervals: [0, 4, 8]),
  ChordFormula(suffix: 'sus2', intervals: [0, 2, 7]),
  ChordFormula(suffix: 'sus4', intervals: [0, 5, 7]),
  ChordFormula(suffix: 'maj7', intervals: [0, 4, 7, 11]),
  ChordFormula(suffix: '7', intervals: [0, 4, 7, 10]),
  ChordFormula(suffix: 'm7', intervals: [0, 3, 7, 10]),
];
```

### 5.2 公式库与和弦识别分离

公式库只负责描述规则，不负责：

-   计算指板音符。
-   判断最低音。
-   处理 UI。
-   决定最终候选排序。

以后增加一个和弦类型，例如 `m7b5`，原则上只需要增加：

``` dart
ChordFormula(suffix: 'm7b5', intervals: [0, 3, 6, 10])
```

然后补充测试。

### 5.3 第一版公式范围

第一批先实现：

-   major
-   minor
-   dim
-   aug
-   sus2
-   sus4

第二批再增加：

-   maj7
-   7
-   m7
-   m7b5
-   dim7
-   add9

暂时不要追求把所有理论和弦都录入。先确保公式和测试正确。

## 六、模块四：实现精确和弦匹配

这是整个和弦解析模块的核心。

### 6.1 为什么需要枚举根音？

假设输入音符是：

``` text
C、E、G
```

如果只拿它和 C major 比较，就只能识别 C major。

但程序并不知道根音一定是 C。因此需要尝试十二个可能的根音：

``` text
C、C#、D、D#、E、F、F#、G、G#、A、A#、B
```

对每个候选根音，计算所有输入音相对于它的半音距离，再与公式库比较。

### 6.2 计算相对音程

``` dart
List<int> getIntervals(
  Set<int> pitchClasses,
  int root,
) {
  return pitchClasses
      .map((note) => (note - root + 12) % 12)
      .toList()
    ..sort();
}
```

例如：

``` dart
final intervals = getIntervals(
  {0, 4, 7, 10},
  0,
);

// [0, 4, 7, 10]
```

与公式 `[0, 4, 7, 10]` 相同，因此可以匹配 C7。

### 6.3 精确匹配流程

建议 `ChordAnalyzer` 第一版按下面的流程实现：

1.  接收已经计算好的 `List<GuitarNote>`。
2.  提取去重后的 `Set<int>`。
3.  如果没有音符，直接返回空列表。
4.  遍历 12 个候选根音。
5.  对每个根音计算相对音程并排序。
6.  遍历公式库。
7.  比较两个排序后的列表是否完全相等。
8.  相等则生成一个候选结果。
9.  遍历结束后返回全部候选。

伪代码：

``` dart
for (final root in allRoots) {
  final intervals = getIntervals(pitchClasses, root);

  for (final formula in chordFormulas) {
    if (listEquals(intervals, formula.intervals)) {
      results.add(
        ChordMatchResult(
          root: root,
          suffix: formula.suffix,
          // 其他字段
        ),
      );
    }
  }
}
```

注意：

-   `listEquals` 可使用
    `package:flutter/foundation.dart`，也可以自己实现列表比较，让核心模块保持纯
    Dart。
-   公式和计算出的音程列表都必须排序，否则相同内容可能因顺序不同而匹配失败。
-   第一版只处理精确匹配，不要在这里偷偷加入缺音规则。

### 6.4 匹配示例

  输入音符      相对音程（以 C 为根音）   结果
  ------------- ------------------------- ---------
  C、E、G       0、4、7                   C major
  C、Eb、G      0、3、7                   C minor
  C、Eb、Gb     0、3、6                   C dim
  C、E、G#      0、4、8                   C aug
  C、D、G       0、2、7                   Csus2
  C、F、G       0、5、7                   Csus4
  C、E、G、B    0、4、7、11               Cmaj7
  C、E、G、Bb   0、4、7、10               C7

### 6.5 为什么要返回候选列表？

同一组音符可能有多个理论解释。不能假设第一个匹配结果就一定是唯一正确答案。

因此接口建议是：

``` dart
List<ChordMatchResult> analyze(List<GuitarNote> notes)
```

而不是：

``` dart
ChordMatchResult? analyze(...)
```

**阶段验收：**
上表测试通过；音符输入顺序变化不影响结果；重复音不影响基础识别；没有精确匹配时返回空列表。

## 七、模块五：设计识别结果模型

建议结果模型不要只存一个拼接好的和弦字符串。

``` dart
class ChordMatchResult {
  final int rootPitchClass;
  final String rootName;
  final String suffix;

  /// 是否完整匹配公式
  final bool isComplete;

  /// 匹配置信度，第一版精确匹配可以先使用 1.0
  final double confidence;

  /// 输入中实际出现的音高类别
  final List<int> matchedPitchClasses;

  const ChordMatchResult({
    required this.rootPitchClass,
    required this.rootName,
    required this.suffix,
    required this.isComplete,
    required this.confidence,
    required this.matchedPitchClasses,
  });
}
```

后续可以逐步增加：

-   `bassPitchClass`：最低音的音高类别。
-   `bassMidiNumber`：最低音的实际音高。
-   `missingIntervals`：缺少的和弦音程。
-   `extraPitchClasses`：公式之外的音。
-   `matchDescription`：匹配原因。
-   `inversion`：转位信息。

第一版不必一次加入所有字段。只保留当前阶段真正需要的内容。

## 八、模块六：增加最低音和转位识别

### 8.1 为什么不能只看音高类别？

以下两组音符的 Pitch Class 集合相同：

``` text
C、E、G
E、G、C
```

但最低音不同：

-   C 最低：通常解释为 C 原位。
-   E 最低：可能解释为 C/E。
-   G 最低：可能解释为 C/G。

因此必须保留每个音的实际音高，而不是只保存 `Set<int>`。

### 8.2 实现步骤

1.  从原始 `List<GuitarNote>` 中找到 MIDI 编号最小的音。
2.  取出最低音的 Pitch Class。
3.  与已识别和弦的根音比较。
4.  如果最低音等于根音，视为原位候选。
5.  如果最低音是和弦中的其他构成音，判断常见转位。
6.  将转位信息附加到候选结果。

三和弦常见情况：

  最低音   转位
  -------- ----------
  根音     原位
  三音     第一转位
  五音     第二转位

注意：吉他弦号从 6 到 1
并不等于音高绝对顺序的通用计算方式。应根据实际音高值判断最低音。

**阶段验收：** 能将 C、C/E、C/G
区分开；同音名出现在不同八度时仍能正确比较高低。

## 九、模块七：增加缺音与模糊匹配

精确匹配要求输入音符与公式中的音程完全一致，但实际吉他指法经常省略某些和弦音。

例如 C major 公式是：

``` text
[0, 4, 7]
```

如果实际只弹出 C 和
E，精确匹配就不会成功。但在某些上下文中，它仍可能是一个省略五音的 C
和弦。

### 9.1 不要直接把所有子集都当成和弦

如果只要输入音符是某个公式的子集就认为匹配，会产生大量误报。

例如只有 C、E 两个音时，可能匹配很多含有 C 和 E 的复杂和弦。

因此需要为不同构成音设置规则和权重。

### 9.2 建议实现步骤

1.  先保留精确匹配逻辑。
2.  精确匹配没有足够结果时，再运行部分匹配。
3.  对每个候选根音和公式，计算已匹配音、缺失音、额外音。
4.  判断缺失的是根音、三音、五音还是扩展音。
5.  为不同缺失情况计算分数。
6.  对包含明显和弦外音的候选扣分。
7.  低于阈值的候选不返回。
8.  在结果中解释匹配原因。

### 9.3 权重思路

可以先采用定性的规则，而不是急着寻找"完美分数"：

-   根音缺失：明显降低可信度。
-   三音缺失：明显降低区分大小调的能力。
-   五音缺失：在部分常见指法中可以接受。
-   七音或扩展音缺失：根据目标和弦类型判断。
-   出现公式之外的音：需要扣分或判为不匹配。

具体权重应通过测试用例逐步调整，不要把某一套分数当成绝对乐理定律。

### 9.4 结果应能解释

例如：

``` text
C major
匹配状态：部分匹配
实际音符：C、E
缺少构成音：G
说明：可能是省略五音的 C 大三和弦
```

**阶段验收：**
能识别合理的省略音指法；能说明缺少什么；不会因为规则太宽松而出现大量无关结果。

## 十、模块八：弦状态必须明确

当前的 `FretboardNote` 如果只记录已选中的弦和品位，就无法区分：

-   用户还没有选择这根弦。
-   用户明确设置这根弦不发声。

建议后续为每根弦增加明确状态：

``` dart
enum StringPlayState {
  unselected,
  open,
  fretted,
  muted,
}
```

状态含义：

  状态         是否参与音符计算   说明
  ------------ ------------------ ----------------
  unselected   暂不参与           用户还没有决定
  open         是                 弹奏空弦
  fretted      是                 弹奏指定品位
  muted        否                 明确不发声

注意：如果用户只选择了部分音符，未选择的弦不应该自动视为闷音。否则算法会把不完整的输入错误地当成完整指法。

## 十一、模块九：如何与现有 dataset 配合

现有 dataset 的作用仍然很有价值，但职责要调整。

### 和弦公式库

负责回答：

> 这组音符在乐理上可能是什么和弦？

例如：

``` text
C、E、G、B -> Cmaj7
```

### 指法 dataset

负责回答：

> 这个和弦有哪些已经收录的吉他按法？

例如：

``` text
Cmajor -> 若干 ChordPosition
```

### 推荐的调用关系

``` text
用户选择指板位置
       │
       ▼
NoteCalculator
       │
       ▼
ChordAnalyzer
       │
       ▼
识别出 C major
       │
       ├──────────────┐
       ▼              ▼
显示和弦信息       查询 dataset
                      │
                      ▼
                展示已收录指法
```

如果 dataset 中没有某个和弦：

-   仍然显示乐理识别结果。
-   可以显示"暂无收录指法"。
-   不应该因此判定识别失败。

也就是说，公式库决定识别能力的范围，dataset 决定可展示的预设指法范围。

## 十二、推荐的整体接口边界

第一版可以先保持简单：

``` dart
class NoteCalculator {
  GuitarNote calculate(FretboardNote position);
}

class ChordAnalyzer {
  List<ChordMatchResult> analyze(List<GuitarNote> notes);
}

class ChordFormula {
  final String suffix;
  final List<int> intervals;
}

class ChordMatchResult {
  final int rootPitchClass;
  final String rootName;
  final String suffix;
  final bool isComplete;
  final double confidence;
}
```

后续再考虑增加：

-   `GuitarTuning`：调弦配置。
-   `StringPlayState`：每根弦的状态。
-   `ChordMatchDetail`：缺音、额外音、匹配原因。
-   `ChordInversion`：转位信息。

不要为了预想中的复杂功能，第一天就建立过多抽象层。

## 十四、第一轮开发任务：先只做这四件事

不要一次把本文全部实现。第一轮建议：

### 任务 1：确认标准调弦

写出六根弦空弦音的配置，并确认弦号方向。

### 任务 2：实现 NoteCalculator

### 任务 3：补充单元测试

## 十五、需要牢记的边界

1.  **音高集合不等于完整音乐语境。** 同一组音符可能有多种和弦解释。
2.  **Pitch Class 不包含八度。**
    它适合公式匹配，但不适合单独判断最低音。
3.  **最低音不一定是根音。** 这正是转位识别需要处理的情况。
4.  **指法数据集不等于和弦理论全集。**
    数据集缺少某个指法，不代表无法识别该和弦。
5.  **模糊匹配不能过度宽松。** 否则两三个音就可能匹配出大量候选。
6.  **音名拼写与音高计算分开。** C# 与 Db
    在十二平均律下音高相同，但乐理拼写可能不同；第一版可先统一使用升号显示，之后再完善。
7.  **识别结果应表达不确定性。**
    返回候选和匹配原因，比只返回一个和弦名称更可靠。

最终目标不是做一个"查指法表"的程序，而是建立一条稳定的数据处理链：

``` text
指板位置 -> 实际音符 -> 音高集合 -> 音程关系 -> 和弦候选
```

只要这条链路设计正确，后续增加和弦公式、调弦方式、转位规则和 UI
展示，都可以逐步扩展，而不需要推翻整个识别模块。
