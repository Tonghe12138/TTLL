# 吉他和弦指板助手 --- Future Roadmap

> 目标：开发一个面向吉他初学者的 Windows + Android
> 应用。用户通过简化指板或音符列表输入音符，应用根据乐理公式推断可能的和弦，并逐步扩展到完整指板、扩展和弦、转位和模糊匹配。

## 一、项目目标与原则

### 第一版目标

1.  将弦号、品位转换成实际音符。
2.  汇总并去重弹奏的音符。
3.  根据和弦构成音公式识别常见和弦。
4.  返回一个或多个候选和弦，而不是强行认定唯一答案。
5.  展示和弦构成音，帮助初学者理解结果。

### 核心原则

-   **乐理公式负责识别，现有 dataset 负责辅助展示。**
    数据集不完整，不应成为识别能力的上限。
-   先做精确匹配，再做缺音、转位和模糊匹配。
-   计算逻辑与 Flutter UI 分离，核心逻辑优先使用纯 Dart。
-   每个阶段都要有明确的输入、输出和单元测试。
-   同一组音符可能有多种乐理解释，识别结果应允许多个候选。

## 三、分阶段开发

## 阶段 0：整理现有模型与数据

**目标：确认现有指板数据和和弦数据的含义。**

-   [ ] 整理 `FretboardNote`：明确 `string`、`fret`、`finger` 的含义。
-   [ ] 明确弦号规则：1 弦是最细的高音弦，6 弦是最粗的低音弦。
-   [ ] 明确品位规则：0 表示空弦，1 及以上表示实际品位。
-   [ ] 检查 `Chord`、`ChordPosition` 的字段定义。
-   [ ] 确认数据集 `frets` 的顺序是否为 6 弦到 1 弦。
-   [ ] 确认 `frets` 中 `-1`、`0`、正数的含义。
-   [ ] 保留现有 dataset，但不再把它作为通用和弦识别的唯一来源。

**验收标准：** 能解释一条 `ChordPosition`
数据；明确"未选择某根弦"和"明确不弹这根弦"不是一回事。

## 阶段 1：实现指板位置到音符的转换

**目标：输入弦号和品位，得到实际音符。**

-   [ ] 定义十二音与半音值的映射：C=0、C#=1、D=2......B=11。
-   [ ] 定义标准吉他调弦：6 到 1 弦依次为 E、A、D、G、B、E。
-   [ ] 实现 `NoteCalculator`。
-   [ ] 计算音高类别（Pitch Class）。
-   [ ] 同时保留八度信息，后续才能判断真实最低音。
-   [ ] 检查非法弦号、负数品位和未配置的弦。

建议模型：

``` dart
class GuitarNote {
  final String name;
  final int pitchClass; // 0~11
  final int midiNumber; // 保留八度信息

  const GuitarNote({
    required this.name,
    required this.pitchClass,
    required this.midiNumber,
  });
}
```

测试用例（标准调弦）：

  指板位置    预期音符
  ----------- ----------
  6 弦空弦    E
  5 弦空弦    A
  5 弦 3 品   C
  4 弦 2 品   E
  3 弦空弦    G
  2 弦 1 品   C
  1 弦空弦    E

**验收标准：**
上述测试全部通过；不同弦上相同音高的计算结果一致；能为一组指板位置生成音符列表。

## 阶段 2：建立基础和弦公式库

**目标：用相对根音的半音数描述和弦。**

-   [ ] 定义 `ChordFormula`，包含和弦后缀与半音列表。
-   [ ] 先支持三和弦和挂留和弦。
-   [ ] 公式数据与识别算法分离，增加新和弦时尽量只增加数据。

第一批公式：

  类型    半音公式   C 调构成音
  ------- ---------- ------------
  major   0, 4, 7    C、E、G
  minor   0, 3, 7    C、Eb、G
  dim     0, 3, 6    C、Eb、Gb
  aug     0, 4, 8    C、E、G#
  sus2    0, 2, 7    C、D、G
  sus4    0, 5, 7    C、F、G

**验收标准：** 可以根据任意根音和公式生成构成音；公式库不为 C、D、E
等每个调重复写规则。

## 阶段 3：实现第一版和弦识别

**目标：识别 major、minor、dim、aug、sus2、sus4。**

-   [ ] 输入指板音符并转换为音高类别。
-   [ ] 去重，避免重复八度影响基础公式匹配。
-   [ ] 枚举 C 到 B 共 12 个可能根音。
-   [ ] 计算每个音相对候选根音的半音距离。
-   [ ] 与公式库进行精确匹配。
-   [ ] 返回所有匹配候选，不只返回第一个。
-   [ ] 处理输入顺序变化和重复音。
-   [ ] 对单音、双音等信息不足的输入返回空结果或低置信度结果。

建议接口：

``` dart

  List<ChordMatchResult> analyze(List<GuitarNote> notes) {

    // 3. 枚举候选根音
    // 4. 计算相对音程
    // 5. 匹配和弦公式
    // 6. 返回候选结果

```

**验收标准：**

-   [ ] C、E、G -\> C major
-   [ ] C、Eb、G -\> C minor
-   [ ] C、Eb、Gb -\> C dim
-   [ ] C、E、G# -\> C aug
-   [ ] C、D、G -\> Csus2
-   [ ] C、F、G -\> Csus4
-   [ ] 输入顺序和重复音不影响识别结果

本阶段只做精确匹配，暂不处理缺音和复杂转位。

## 阶段 4：增加七和弦与扩展和弦

**目标：支持项目第一版计划中的扩展和弦。**

-   [ ] 增加 maj7、m7、属七 7。
-   [ ] 增加 m7b5、dim7。
-   [ ] 增加 add9。
-   [ ] 视进度增加 6、m6、mMaj7、9 等。
-   [ ] 为每个公式增加测试，检查公式之间的歧义。

  类型   半音公式      C 调构成音
  ------ ------------- ---------------
  maj7   0, 4, 7, 11   C、E、G、B
  7      0, 4, 7, 10   C、E、G、Bb
  m7     0, 3, 7, 10   C、Eb、G、Bb
  m7b5   0, 3, 6, 10   C、Eb、Gb、Bb
  dim7   0, 3, 6, 9    C、Eb、Gb、A
  add9   0, 2, 4, 7    C、D、E、G

**验收标准：** 第一版要求的 maj7、m7、sus2、sus4、dim、aug
均可识别；新增公式不需要重写核心匹配流程。

## 阶段 5：识别最低音与转位

**目标：区分音高集合相同、但最低音不同的和弦。**

例如：

-   C、E、G，最低音 C -\> C

-   E、G、C，最低音 E -\> C/E

-   G、C、E，最低音 G -\> C/G

-   [ ] 在音符模型中保留八度或 MIDI 音高。

-   [ ] 根据实际音高找到最低音，不能简单按弦号判断。

-   [ ] 判断最低音是否为和弦根音。

-   [ ] 支持常见三和弦转位。

-   [ ] 后续扩展七和弦转位。

-   [ ] 结果中分别记录和弦根音与实际最低音。

**验收标准：** 能区分
C、C/E、C/G；不同弦上出现相同音名时，仍能正确判断最低音。

## 阶段 6：支持缺音与模糊匹配

**目标：处理真实吉他指法中省略部分和弦音的情况。**

-   [ ] 区分精确匹配与部分匹配。
-   [ ] 允许部分构成音缺失，但降低置信度。
-   [ ] 对根音、三音、五音、七音设置不同权重。
-   [ ] 标记和弦外音，不要一律忽略。
-   [ ] 处理不同八度的重复音。
-   [ ] 返回匹配原因，例如"完整匹配""缺少五音""缺少根音"。
-   [ ] 设置置信度阈值，过滤明显不合理的候选。

建议原则：

-   缺少五音通常比缺少三音更容易接受。
-   缺少根音时仍可能识别出和弦，但应降低置信度。
-   三音对区分大三和弦与小三和弦非常重要。
-   和弦外音需要结合具体公式判断，不能全部忽略。

**验收标准：**
能识别部分省略构成音的常见指法，并说明缺少哪些音；不会因为匹配过于宽松而返回大量无关结果。

## 阶段 7：完善弦状态与完整指板交互

**目标：让 UI 准确表达用户实际弹奏的内容。**

-   [ ] 为每根弦定义状态：未选择、空弦、按弦、闷音。
-   [ ] 未选择不等于闷音。
-   [ ] 只有明确参与弹奏的弦才进入音符计算。
-   [ ] 闷音弦不产生音符。
-   [ ] 支持点击指板设置品位、清除选择。
-   [ ] 显示音名、弦号、品位和手指编号（如果有）。
-   [ ] 修改指法后实时更新识别结果。

**验收标准：**
用户可以明确设置六根弦的状态；闷音弦不会参与识别；未选择的弦不会被误认为闷音；修改音符后结果正确更新。

## 阶段 8：调弦配置与现有数据集整合

**目标：支持不同调弦，并让现有指法数据集发挥作用。**

-   [ ] 将标准调弦抽象为可配置数据。
-   [ ] 支持选择或自定义调弦。
-   [ ] `NoteCalculator` 根据当前调弦计算音符。
-   [ ] 检查现有 `Chord` / `ChordPosition` 数据。
-   [ ] 将常见指法数据用于和弦详情展示。
-   [ ] 根据识别结果推荐数据集中对应的指法。
-   [ ] 数据集中没有对应指法时，仍然显示乐理识别结果。

**验收标准：**
切换调弦后音符计算正确；数据集缺少某个和弦时，不影响公式识别。

## 阶段 9：候选排序与体验优化

**目标：让识别结果更符合普通吉他使用者的理解。**

-   [ ] 完整匹配优先于部分匹配。
-   [ ] 根音与最低音一致可作为排序参考。
-   [ ] 常见和弦类型优先展示。
-   [ ] 展示构成音、根音、最低音和转位信息。
-   [ ] 对有歧义的结果给出简短说明。
-   [ ] 允许用户展开查看其他候选。

**验收标准：**
常见指法的首选结果合理；歧义结果可以查看；用户能理解结果为什么是这个和弦。

## 五、优先级建议

### 第一版必须完成

1.  阶段 0：整理现有模型。
2.  阶段 1：指板位置转音符。
3.  阶段 2：基础和弦公式库。
4.  阶段 3：基础和弦识别。
5.  阶段 4：支持指定的扩展和弦。
6.  一个简化 UI：可以选择音符并展示识别结果。

### 第一版之后再做

-   转位和弦。
-   缺音与模糊匹配。
-   完整六弦指板交互。
-   自定义调弦。
-   智能候选排序。
-   更多复杂扩展和弦。

### 暂时不要做

-   不要试图一次性收录所有和弦名称。
-   不要为每个根音、每种指法写独立规则。
-   不要在 Flutter Widget 中直接计算乐理。
-   不要仅凭音高集合承诺唯一识别结果。
-   不要在基础音符计算未通过测试时开发复杂识别算法。

## 六、最终完成标准

-   [ ] Windows 和 Android 均能正常运行。
-   [ ] 用户可以通过简化指板或音符列表输入音符。
-   [ ] 应用根据当前调弦正确计算音符。
-   [ ] 能识别 major、minor、dim、aug、sus2、sus4。
-   [ ] 能识别 maj7、m7 等第一版要求的扩展和弦。
-   [ ] 能返回多个候选并展示构成音。
-   [ ] 现有 dataset 用于指法展示和推荐，不再限制识别范围。
-   [ ] 核心乐理计算有单元测试。
-   [ ] 后续可以通过增加公式扩展和弦类型，而不必重写识别流程。

## 七、现在立刻开始做什么

先完成阶段 0 和阶段 1，不要同时推进多个阶段：

1.  确认 `FretboardNote` 和 `Guitar` 的现有定义。
2.  确认标准调弦的六根空弦音。
3.  编写 `NoteCalculator`，让 6 弦空弦、5 弦 3 品、4 弦 2
    品等测试全部通过。

完成后再进入和弦公式库与识别算法。每一步都要有明确的输入、输出和验收标准，适合边学习
Flutter、边学习基础乐理。
